1 Executive Summary

Garuda Kavach is a defense-in-depth, real-time Intrusion Detection System (Drone IDS) purpose-built for MAVLink-communicating Unmanned Aerial Vehicles (UAVs). In contemporary civilian and defense drone ecosystems, MAVLink (v1 and v2) prioritizes low-bandwidth serialization over cryptographic integrity. Because production deployments frequently leave optional MAVLink signing disabled due to key-management overhead, UAVs are exposed to commodity Software Defined Radio (SDR) exploits, including GPS manipulation, unauthorized flight-mode transitions, airborne disarming, and kinematic control override.

Key Innovations: Rather than demanding impractical wholesale protocol replacement, Garuda Kavach operates as an inline and ground-side security layer featuring an 8-layer hybrid detection core that concurrently correlates physical kinematics, statistical thresholds, unsupervised machine learning, and protocol sequence dynamics. Alerts and telemetric command states are cryptographically signed with HMAC-SHA256 in an authenticated envelope with strict replay protection (<60s age gate, nonces). Immediate autonomous countermeasures (ArduCopter Mode 17: BRAKE, Mode 6: RTL, or LAND) are dispatched directly to the flight controller prior to physical trajectory loss.

Target Platforms & Data Sources: Tailored for ArduPilot and PX4 autopilots deployed on SITL simulators and physical companion computers (Raspberry Pi 4/5, NVIDIA Jetson). Monitored data sources comprise the raw telemetry stream: HEARTBEAT, GLOBAL_POSITION_INT, VFR_HUD, ATTITUDE, SYS_STATUS, COMMAND_LONG, and PARAM_VALUE.

Current Status: Fully operational Stage 1 prototype. End-to-end integration tested across a 3-node distributed Tailscale network linking the SITL Drone Simulator, the M3 Detection Engine, and the M5 Tactical Operator Console. All 10 attacker scripts are actively detected with automated failsafe mitigation.

2 Understanding of the Problem

UAV Cyber-Threat Landscape: Modern autonomous UAV missions rely on unencrypted telemetry links (915MHz, 2.4GHz, 433MHz, Wi-Fi, and LTE). Attackers equipped with sub-$100 HackRF/BladeRF transceivers or network tap proxies can execute unauthorized packet injection without needing physical access to the aircraft.

Primary Attack Surfaces:

  • RF / Communication: MAVLink command flooding (DoS), packet replay, and buffer exhaustion.
  • Navigation: GPS coordinates jumping, gradual position drift, and false velocity injection.
  • Flight Control: Rogue DO_SET_MODE commands, uncommanded yaw spin, mid-flight motor disarm, and forced takeoff/landing.

Limitations of Existing Approaches:

  • Signature-Only Firewalls: Fail against zero-day kinematic anomalies or continuous parameter tampering.
  • Heavy Deep Learning on Edge: High inference latency (>100ms) consumes onboard compute and fails real-time deadlines.
  • Unauthenticated Alarm Dashboards: Conventional IDS tools send unencrypted alarms; an adversary can spoof alarms to force false aborts.

The Garuda Kavach Advantage: Zero trusted wire. Every pipeline hop is authenticated, detection latency is deterministic (≤15ms), and physical dynamics (EKF residual) check sensor consistency regardless of what forged GPS reports.

3 Proposed Drone IDS Architecture

Garuda Kavach enforces a four-stage security pipeline: (1) Flight & Ingress Layer → (2) Eight-Layer Detection Core → (3) Autonomous Mitigation Engine → (4) Tactical Operator Console.

Layer Detection Methodology Target Data Source Detection Indicator & Security Function
L1: Rate Limiter Sliding token bucket rate counter MAVLink Stream UDP/Serial Flags packet bursts exceeding baseline rate (>100 Hz / >1000 pkt/s DoS flood).
L2: Sequence Validator Packet sequence monotonicity tracking MAVLink Packet Header (seq) Identifies packet replay, drop spikes, and injected non-sequential frames.
L3: EKF Physics Extended Kalman Filter dynamic residual (NIS) GLOBAL_POSITION_INT vs IMU Calculates kinematic residual r = ||x_GPS - x_EKF||; spikes when position violates physics.
L4: Statistical Rules Phase-adaptive envelope bounds VFR_HUD, ATTITUDE Detects vertical velocity vs altitude divergence (|vz| > 5 m/s during cruise).
L5: Isolation Forest Unsupervised multivariate anomaly detection 9-D Engineered Feature Vector Decision score outlier threshold (≤ -0.05); captures unseen coupled anomalies.
L6: Adaptive Thresholds Rolling statistical percentile updating Flight-phase state estimator Adapts normal operational baselines across Takeoff, Cruise, Hover, and Landing.
L7: Command Monitor Flight controller state machine auditing COMMAND_LONG, HEARTBEAT Intercepts unauthorized arm/disarm transitions, mode switches, and rogue yaw commands.
L8: HMAC Signing HMAC-SHA256 envelope verification Inter-module JSON transport Prevents adversary from forging alerts; enforces 60-second replay window with nonces.

Feature Extraction & Data Strategy: From raw binary telemetry, the engine derives a 9-dimensional sliding window vector: (1) mean speed, (2) horizontal acceleration Δv_xy, (3) vertical jerk Δa_z, (4) yaw rate ψ̇, (5) roll/pitch variance, (6) command ACK frequency, (7) inter-arrival jitter, (8) packet rate (Hz), and (9) EKF normalized innovation squared (NIS). Baselines are fit to recorded normal autonomous waypoints.

Cryptographic Incident Forensics: Every alert logged into the incident ledger contains: {timestamp, attack_type, confidence, source, latency_ms, failsafe_mode}. The record is encapsulated in an HMAC-SHA256 signature envelope and sequentially hash-chained. The operator console alerts highlight with forensic ID and color coding.

4 Platform Integration & Interoperability

Flight Controller Compatibility: Seamlessly integrates with ArduPilot (ArduCopter / ArduPlane) and PX4 autopilot firmware. Connects via standard telemetry interfaces: UART/Serial (TELEM1/TELEM2) on physical aircraft or UDP ports (69, 14550, 14551, 14556) in SITL simulation.

Avionics Resource Footprint: Adheres to strict flight controller resource safety limits. Ingestion and lightweight EKF/rule evaluations consume ≤ 18% CPU on quad-core ARM Cortex-A72 (Raspberry Pi 4) and < 45MB RAM, ensuring zero interference with real-time flight navigation threads.

Multi-Port Resilient Ingress: The backend runs a concurrent multi-threaded MAVLink listener polling across candidate ports simultaneously, guaranteeing automatic lock onto live simulator or physical radio feeds without manual port configuration.

Automated Closed-Loop Mitigation: Upon threat confirmation (≥ 0.50 confidence), the mitigation engine immediately issues a prioritized MAVLink command directly to the drone:

  • Kinematic / Command Spoofing: Mode 17 (BRAKE) — halts vehicle in place.
  • Navigation / Loss-of-Link: Mode 6 (RTL) — autonomous Return-To-Launch.

Accuracy & Performance Benchmarks:

  • Detection Recall: 100% across all 10 adversarial test scripts.
  • False Positive Rate (FPR): < 0.8% evaluated over 60 min normal flight.
  • Mean Failsafe Latency: 11.4 ms (well beneath 50ms requirement).

Failure Handling & Fallback: If primary network transport experiences packet drop, the system relies on local sliding-window EKF state and falls back to local autopilot failsafe. If link drops, console auto-disconnects within 3s without displaying ghost flight.
